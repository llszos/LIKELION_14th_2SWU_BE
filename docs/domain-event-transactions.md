# 관계 해제 이벤트의 트랜잭션 계약

## 적용 범위

관계 해제 후 상황 참여와 도움 요청·지정, 공유 권한을 정리하는 A→B→C→D 이벤트 흐름에 적용합니다.

## 처리 시점

- `RelationshipService.endRelationship()`은 관계 상태를 변경한 트랜잭션 안에서 `RelationshipEndedEvent`를 발행합니다.
- 이벤트는 같은 애플리케이션 안에서 동기 처리합니다. B의 관계 정리 리스너는 A 트랜잭션에 참여하고, 실제 참여 상태가 `REMOVED`로 변경되면 `SituationParticipantRemovedEvent`를 발행합니다.
- C는 참여 종료 이벤트에 따라 상황 내 요청·지정을 정리하고 D의 권한 회수 흐름을 이어갑니다.
- A·B·C·D의 DB 변경은 같은 트랜잭션 매니저와 트랜잭션에 참여해야 합니다. 리스너는 예외를 삼키거나 비동기·독립 트랜잭션으로 분리하지 않습니다.

## 실패 처리

B, C, D 중 어느 단계에서든 예외가 발생하면 예외를 A 호출부까지 전파하고 A 관계 해제를 포함한 전체 DB 변경을 롤백합니다. 동일 흐름을 커밋 후 처리나 비동기 처리로 바꾸면 A 변경을 되돌릴 수 없고 재시도 책임도 달라지므로, outbox 등 전달 보장 방식을 포함해 계약을 다시 합의해야 합니다.

## 통합 검증 기준

최신 develop과 A·B·C·D 구현을 함께 구성한 MySQL 통합 테스트에서 확인합니다.

- MY_PERSON 단방향 및 GUARDIAN 양방향 관계 해제가 B 참여 정리, C 요청·지정 정리, D 권한 회수로 이어지는지 확인합니다.
- B, C, D 각 처리 단계에서 실패를 주입하고, 별도 트랜잭션에서 A 관계·B 참여·C 요청·지정·D 권한이 모두 이전 상태로 롤백됐는지 확인합니다.
- 실패 원인을 제거한 재시도가 각 상태를 한 번씩만 변경하고 이벤트를 중복 처리하지 않는지 확인합니다.
- 관계 해제와 참여자 추가가 경합할 때 종료된 관계의 사용자가 ACTIVE 참여자로 남지 않는지 확인합니다.

이 검증은 개별 PR의 단위 테스트나 CI 성공만으로 대체하지 않습니다.
